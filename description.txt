Поэтапная проверка выполнения скриптов ./parser
Проверка осуществляется через тестовые скрипты ./scripts

1) python ~/lord_parser/scripts/init_db.py - создать БД
    recreate_db.py - пересоздать БД (!!! удалив содержимое)
2) python ~/lord_parser/scripts/test_url_generator.py - проверить генератор ссылок вида https://wk.lordfilm17.ru/filmy/2025/page/1/ (в БД не записи не создает, отдельного запуска не требует)
3) python ~/lord_parser/scripts/test_link_parser.py - проверить собираемые ссылки на фильмы со страницы вида https://wk.lordfilm17.ru/filmy/2025/page/1/ и отправляет их в БД
4) python ~/lord_parser/scripts/test_db_links.py - проверить сохраненные ссылки в БД
5) python ~/lord_parser/scripts/test_film_parser.py - проверить сбор деталей фильма и отправку их в БД
6) python ~/lord_parser/scripts/test_db_film_details.py - проверить детали фильмов сохраненные в БД

Общая логика шедулера scheduler

text
scheduler (тестовый конфиг)
    → link_parser (сбор ссылок + сохранение в БД)
    → film_parser (парсинг деталей + обновление БД)
    → [БД НАПОЛНЕНА] ← это состояние, а не этап
    → тестовый запрос (эмуляция бота)
📊 Что действительно происходит на каждом этапе:
link_parser:
Парсит страницы каталога

Сразу сохраняет ссылки в таблицу films

Создает записи в parsing_sessions и parsing_history

film_parser:
Берет URL из таблицы films

Парсит детали фильмов

Сразу обновляет записи в таблице films

Обновляет parsing_sessions и parsing_history

🎯 Правильная архитектура тестирования:
text
scheduler (тестовый конфиг)
    │
    ├── link_parser → БД (добавляет URL фильмов)
    │
    └── film_parser → БД (дополняет метаданные)
          │
          └── [БД ГОТОВА] → тестовые запросы
БД - это общее хранилище, куда оба парсера пишут данные, а не отдельный этап обработки.

После выполнения film_parser БД уже содержит все необходимые данные для работы бота - можно сразу переходить к тестовым запросам! ✅
